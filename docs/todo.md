# 待办（todo）

待办是跬步的第二类 Markdown 数据，平铺存放在工作台的 `todos/` 目录，支持飞书任务式的详情、附件、链接与子任务，录入步骤尽量少。

## CLI 用法

所有 `todo` 子命令都支持 `--json` 与 `--workspace <dir>`，参数与位置参数可混排；成功退出码 0，找不到待办退出 1（JSON 错误码 `NOT_FOUND`），找不到工作台退出 10（`NOT_OPEN`）。

| 命令 | 说明 |
| --- | --- |
| `todo add "<文本>" [--due <值>] [--tag t]... [--parent <id>] [--raw] [--dry-run] [--body/--file/--stdin]` | 快速录入待办；文本可由多个位置参数拼接 |
| `todo list [--view today\|week\|all\|done] [--status todo,doing\|all\|...] [--due today\|tomorrow\|week\|overdue] [--tag t]... [--parent <id>\|--root] [--search <词>] [--tree]` | 列出待办（走索引，先增量同步）；`--view` 与 App 侧栏分组一致：today = 有截止且不晚于今天（含逾期），week = 截止在本周，all = 全部未完成，done = 已完成 / 已取消；不能与 `--status` / `--due` 同用 |
| `todo show <id>` | 查看待办详情（含正文、子任务、链接、附件） |
| `todo done <id>` / `todo reopen <id>` / `todo start <id>` / `todo cancel <id>` | 变更状态；`done` / `cancel` 时若还有未完成子任务，必须加 `--with-children`（连同全部后代）或 `--only-parent`（只改本条），否则退出 8（`NEEDS_CONFIRM`）并说明子任务数 |
| `todo edit <id> [--title t] [--due <值>\|--no-due] [--tag t ...] [--status s] [--body/--file/--stdin]` | 修改待办，至少给一个修改项 |
| `todo sub <id> "<文本>"` | 新增子待办，等价于 `todo add "<文本>" --parent <id>` |
| `todo link <id> <url> [--title t]` / `todo unlink <id> <url>` | 管理链接 |
| `todo attach <id> <file>` / `todo detach <id> <相对路径>` | 管理附件，attach 输出附件相对路径 |
| `todo mv <id> [--parent <id>\|--root] [--position n]` | 移动待办 |
| `todo rm <id> [-r\|--recursive]` | 删除待办；有子任务且无 `-r` 时返回 `HAS_CHILDREN` |

`todo add` 默认对文本做快速录入解析；`--raw` 跳过解析把整段当标题；`--due` 优先于文本解析出的日期，其值既接受 `store.ParseDue` 的格式，也接受快速录入日期表达（如 `明天`、`周四 15:00`）；`--due ""` 等价于不设截止。

## 快速录入规则

`core.ParseQuickAdd(text, now)` 只识别第一处日期表达（最左匹配，同位置取最长），后续日期原样留在标题；时间可紧跟日期（中间允许空格），没有日期时取第一处时间表达且日期为今天；标签 `#xxx` / `＃xxx` 必须位于开头或空白之后，内容不能为空且不能是纯数字。解析后标题为空时回退为原始输入去首尾空白。

小时的写法支持阿拉伯数字与中文数字（`零`/`〇`、`一`~`九`、`两`、`十`、`十X`、`X十`、`X十Y`，有效范围 0~23），分钟支持 `半`=30、`一刻`=15、`三刻`=45、中文/阿拉伯数字分钟与 `X分`。为避免误判，只有「点」前是数字（中文或阿拉伯）时才算时间，且数字串中间不重新起匹配（`二十五点` 整体非法，不会退化成 `十五点`），`一点点`、`重点`、`第3点` 都不识别。

以下规则基于 `now = 2026-10-26 10:00 Asia/Shanghai`（周一）：

| 输入 | 解析结果 | 说明 |
| --- | --- | --- |
| `今天交方案` | 截止 2026-10-26，标题「交方案」 | `今天`/`今日` |
| `明天交方案` | 截止 2026-10-27，标题「交方案」 | `明天`/`明日` |
| `后天交方案` | 截止 2026-10-28，标题「交方案」 | `后天` |
| `大后天交方案` | 截止 2026-10-29，标题「交方案」 | `大后天` |
| `周一交方案` | 截止 2026-10-26，标题「交方案」 | `周X`，周一 = 今天 |
| `周日交方案` | 截止 2026-11-01，标题「交方案」 | `周X` 从今天起取最近一天 |
| `本周一交方案` | 截止 2026-10-26，标题「交方案」 | `本周X`/`这周X`，周一为一周开始 |
| `下周一 15:00` | 截止 2026-11-02 15:00 | `下周X`，时间紧跟日期 |
| `下周三下午3点` | 截止 2026-11-04 15:00 | `下午` 且 N<12 时 +12 |
| `10-30 交方案` | 截止 2026-10-30，标题「交方案」 | `M-D`，今年，早于今天取明年 |
| `10/30` | 截止 2026-10-30 | `M/D` |
| `10月30日` | 截止 2026-10-30 | `M月D日`；`M月D号` 同 |
| `1-5` | 截止 2027-01-05 | 早于今天（1-5 已过）取明年 |
| `2-30` | 不识别，标题「2-30」 | 月日非法不识别 |
| `2026-11-02` | 截止 2026-11-02 | `YYYY-MM-DD` |
| `2026年11月2日` | 截止 2026-11-02 | `YYYY年M月D日` |
| `v1.10-2` | 不识别，标题「v1.10-2」 | 前后紧挨数字/`.` 不误判 |
| `1.2` | 不识别，标题「1.2」 | `M.D` 不识别，避免版本号冲突 |
| `每周一次例会` | 不识别，标题「每周一次例会」 | `周X` 前一个字是 `每` 时不识别 |
| `15:00 开会` | 截止今天 15:00，标题「开会」 | 只有时间没有日期 → 日期取今天 |
| `晚上8点` | 截止今天 20:00 | `晚上` 且 N<12 时 +12 |
| `中午12点` | 截止今天 12:00 | `中午` 且 N<11 时才 +12 |
| `傍晚6点` | 截止今天 18:00 | `傍晚` 同 `下午`/`晚上` 规则 |
| `凌晨三点` | 截止今天 03:00 | `凌晨` 不加 12 小时 |
| `三点开会` | 截止今天 03:00，标题「开会」 | 中文数字小时，无时段前缀 |
| `下午三点` | 截止今天 15:00 | 中文数字 + 时段前缀 |
| `十点半` | 截止今天 10:30 | `半` = 30 分 |
| `下午三点半` | 截止今天 15:30 | 中文小时 + `半` |
| `晚上八点一刻` | 截止今天 20:15 | `一刻` = 15 分 |
| `九点十五` | 截止今天 09:15 | `点` 后直接跟中文分钟 |
| `九点05` | 截止今天 09:05 | `点` 后直接跟阿拉伯分钟（两位） |
| `九点零五` | 截止今天 09:05 | `零X` 形式分钟 |
| `十一点三刻` | 截止今天 11:45 | `三刻` = 45 分 |
| `十二点` | 截止今天 12:00 | `十X` 形式 |
| `上午十点` | 截止今天 10:00 | `上午` 不加 12 小时 |
| `两点` | 截止今天 02:00 | `两` = 2 |
| `下午3点半` | 截止今天 15:30，标题回退 | 阿拉伯小时 + 中文分钟 |
| `二十三点` | 截止今天 23:00 | `X十Y` 形式，24 点不支持 |
| `零点` | 截止今天 00:00 | `零` = 0 |
| `二十五点` | 不识别，标题「二十五点」 | 超出 0~23，且不在数字串中间重新匹配 |
| `一点点建议` | 不识别，标题「一点点建议」 | `点` 前不是数字 |
| `重点看文档` | 不识别，标题「重点看文档」 | `点` 前不是数字 |
| `第3点要求` | 不识别，标题「第3点要求」 | `点` 前有 `第` |
| `三点式` | 截止今天 03:00，标题「式」 | 已知行为：无法在不误伤「三点开会」的前提下区分 |
| `明天下午三点` | 截止 2026-10-27 15:00 | 中文时间紧跟日期 |
| `十点半 #工作` | 截止今天 10:30，标签 `工作` | 时间后可接标签 |
| `月底交方案` | 截止 2026-10-31，标题「交方案」 | `月底` = 本月最后一天 |
| `月底下午三点` | 截止 2026-10-31 15:00 | `月底` 可跟时间 |
| `下月底交方案` | 截止 2026-11-30 | `下月底`/`下个月底` = 下月最后一天 |
| `下个月底交方案` | 截止 2026-11-30 | 同上 |
| `月底`（12 月 10 日） | 截止 2026-12-31 | 12 月 `下月底` 跨年到 2027-01-31 |
| `月底`（10 月 31 日当天） | 截止 2026-10-31 | 今天已是月底当天即今天 |
| `#工作 #框架组` | 标签 `工作`、`框架组` | 多个标签，去重保持顺序 |
| `#123 开会` | 无标签，标题「#123 开会」 | 纯数字不算标签 |
| `周四交方案#评审` | 截止 2026-10-29，无标签 | `#` 前无空白则不当标签 |
| `明天 #工作` | 截止 2026-10-27，标签 `工作` | 只剩日期与标签，标题回退为原文 |
| `多个日期 明天 后天` | 截止 2026-10-27，标题「多个日期 后天」 | 多个日期只取第一个 |

## KUIBU_NOW

CLI 取「现在」的函数优先读取环境变量 `KUIBU_NOW`（RFC3339，例如 `2026-10-26T10:00:00+08:00`），未设置时才用 `time.Now()`。所有待办命令的创建/更新/完成时间、日期解析与到期过滤都使用它。它只用于测试与脚本复现，日常使用不要设置。

```bash
KUIBU_NOW=2026-10-26T10:00:00+08:00 kuibu todo list --due overdue --json
```

## 给 App（Mac 待办界面）的接口说明

App 与 CLI 共用同一套 Go 核心库，推荐直接调用以下 API：

**存储（`internal/store`）**

- `ws.CreateTodo(store.NewTodo{...})`：新建待办；`NewTodo` 含 `Title/Body/Parent/Tags/Due/Status/Links/Source/Now`。
- `ws.GetTodo(id)` / `ws.ListTodos()`：读取单条 / 全部待办（含正文）。
- `ws.UpdateTodo(id, now, func(*Todo) error)`：通用修改，自动维护 `updated` 与 `done_at`。
- `ws.SetTodoStatus(id, status, now)`：`todo`/`doing`/`done`/`canceled` 状态切换。
- `ws.AddTodoLink(id, link, now)` / `ws.RemoveTodoLink(id, url, now)`：管理链接（同 URL 去重）。
- `ws.AttachTodoFile(id, srcPath, now)` / `ws.DetachTodoFile(id, rel, now)`：管理附件（内容哈希去重）。
- `ws.MoveTodo(id, newParent, position)` / `ws.DeleteTodo(id, recursive)`：移动与删除。
- `store.ParseDue(s)` / `store.TodoLocation()`：截止字符串解析与时区。

**快速录入（`internal/core`）**

- `core.ParseQuickAdd(text, now)`：返回 `QuickAdd{Input, Title, Due, Tags, Matches}`，App 的「最少录入」输入框直接用。
- `core.DueRange(kind, now)`：`today`/`week`/`tomorrow` 的日期范围。

**索引（`internal/index`）**

- `idx.ListTodos(index.TodoFilter{...})`：过滤列表；`TodoFilter` 支持 `Statuses/Tags/Parent/DueFrom/DueTo/OverdueAt/Query/Limit`。
- `idx.GetTodo(id)` / `idx.TodoChildren(parent)`：单条与子任务元数据。
- `idx.Sync(ctx)`：外部改文件后的增量同步（App 打开工作台与每次读写前可调用）。

**监听（`internal/index`）**

- `index.Watch(ctx, ws, idx, onChange)`：`onChange` 收到 `Event`；笔记变化在 `Changes/IDs`，待办变化在 `TodoChanges/TodoIDs`，两者互不混入。App 可据此分别刷新笔记树与待办列表。

## App 待办界面（里程碑 2 C 线）

App 的待办界面是「轻量版飞书任务」：录入步骤尽量少，详情、附件、链接、子任务
直接在一次操作里完成。所有读写都经 `TodoService`（`app/todoservice.go`）调用上面的
核心库 API，前端不拼路径、不解析 Markdown。

### 视图切换

主窗口最左侧是窄图标栏：`✎` 笔记、`✓` 待办，下面是工作台与设置入口。切到待办后
整个主区域换成待办视图，笔记的树与编辑器不显示；切走前会先把当前笔记存盘。
上次的视图存在 `localStorage`（`kuibu.view`），下次启动直接恢复。

### 列表视图

左侧窄栏：

| 分组 | 定义 | 实现 |

| 今天 | 今天截止 + 已逾期 | `due_date <= 今天` 且状态为 `todo`/`doing`，逾期项标红 |

中间列表：

- 顶部快速录入框，占位「添加待办，如：明天下午三点 交周报 #工作」。输入时用
  `core.ParseQuickAdd` 实时预览（截止、标签、标题），回车即建；建完清空并保持焦点。
  在「今天」分组里录入不会强加今天日期，完全按解析结果（没解析出日期就没有截止）。
- 旁边是搜索框，按标题与正文检索（`index.TodoFilter.Query`）。
- 列表项：勾选框（完成/取消完成）、标题、截止（今天/明天/周X/日期，逾期红色）、
  标签、子任务进度（如 `0/2`）。子任务在父任务下缩进显示，可折叠。已完成项划线弱化。
- 点一条在右侧打开详情面板（列表收窄），面板右上角关闭。

### 详情面板

| 区块 | 交互 |
| --- | --- |
| 标题 | 行内编辑，回车或失焦保存 |
| 状态 | 四个分段按钮：未开始 / 进行中 / 已完成 / 已取消 |
| 截止 | 文本输入支持快速表达（`明天下午三点`），回车或失焦保存；另有日期 + 时间控件；可「清除」 |
| 标签 | 输入框回车添加（支持空格/逗号分隔、可带 `#`），点标签上的 ✕ 移除 |
| 详情 | 复用笔记的 Milkdown（Crepe）编辑器，600ms 防抖保存，关闭面板前再存一次 |
| 子任务 | 列表 + 勾选；底部输入框回车即建，同样走 `ParseQuickAdd` |
| 链接 | URL + 可选标题，未填标题显示「域名+路径」；点击用系统浏览器打开；可删除 |
| 附件 | 「选择文件」走原生对话框，或把文件拖进详情面板；存入 `assets/`（`AttachTodoFile`），点文件名用系统默认程序打开，可移除 |
| 来源笔记 | `todo.Source` 有值时显示笔记标题，点击切到笔记视图并打开该笔记 |

截止的文本输入与日期/时间控件是同一个字段的两种输入方式：都用
`TodoService.UpdateDue`，文本为空即清空截止。

### 完成父任务的确认

完成父任务时若还有未完成的子任务，弹应用内模态（与现有弹窗同一样式）：

- 「一起完成」：父任务与全部后代一起置为 `done`（`SetStatus(id, "done", true)`）
- 「只完成父任务」：只改父任务
- 「取消」：什么都不做

列表的勾选框与详情面板的状态按钮走同一套判断（先 `OpenChildrenCount`）。

这些规则都在核心库，App 只是薄封装，CLI 行为一致：`store.SetTodoStatusTree`（本条 + 后代）、
`store.OpenDescendantCount`（未完成后代数）、`core.TodoViewStatuses` / `core.InTodoView`（视图过滤）、
`core.TodoOverdue`（逾期判断）、`store.TodoAttachmentPath`（附件只允许列表里、落在 `assets/` 内的文件）。

### 随手记小窗的待办模式

随手记小窗（`/?view=quicknote`）顶部有「笔记 / 待办」小分段指示，也可点击切换；
**Tab 键**在两种模式间切换（输入法组合输入中不切换）。上次的模式存在
`localStorage`（`kuibu.quicknote.mode`）。

待办模式下单行/多行均可：

1. 第一行按 `core.ParseQuickAdd` 解析（实时预览截止与标签）；
2. 其余行原样作为待办正文；
3. `⌘Enter` 保存为待办（`store.CreateTodo`），保存后小窗关闭，主窗口待办列表
   通过 `todo:changed` 事件刷新。

第一行为空时把正文第一段当标题，避免生成空标题待办。

### 事件 `todo:changed`

`WorkspaceService` 的 `index.Watch` 回调里，`Event.TodoIDs` 非空时发
`todo:changed`，数据 `{ ids: string[] }`（笔记变化仍发 `workspace:changed`，
两者互不混入）。前端待办视图收到后刷新列表、分组数量、标签与当前详情；
当前详情被外部删除时关闭面板并提示。

App 自己的写入也会触发这个事件（文件监听没有「谁写的」概念），前端按笔记编辑
器同样的思路处理：正在编辑的标题/正文不被外部刷新覆盖——标题与截止用「是否正在
编辑」标志隔离，正文只在本地没有未保存修改时才采用外部值。
