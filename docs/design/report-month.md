# 月报：从周组报拉出来，按项目整理

> 状态：**已实现（2026-10-28）**。核心库 / CLI / App 已按本稿落地：确定性拼装、本期周范围、
> 按项目独立草稿；已通过 Go 测试与前端 typecheck/build，**未在 Wails 真机 GUI 点验**。
> 交互原型 [`report-month.html`](report-month.html) 仍可点着看（示例数据）。
> 目标：周报已经按「报送项目」分别定稿，月报不再重新读组员原文，而是把**本期各周**已定稿的按项目组报
> 拉出来，去重、按项目分成「本月总结 / 下月计划」，每个项目各出一份月报，独立保存、定稿、导出。
> 月初 / 月末可手动调整「本期包含哪些周」。
>
> 截图见 [`screens/`](screens/) 下 `month-*.png`。

## 一、一句话

```
本期各周已定稿的按项目组报
  → ① 拉取周报（自己勾本期周范围与周组报；缺周显式确认）
  → ② 项目预览（按项目看「本月总结 / 下月计划」，可拖动、可结转、可预览）
  → ③ 整理月报（每个项目一份独立草稿：保存 / 定稿 / 导出 / 复制飞书）
```

与周报三步流程（筛选 → 项目分拣 → 分别整理）同一套骨架，区别是**候选来源从「组员原文」换成
「已定稿的按项目组报」**，月报不重复做逐条筛选。

## 二、放在现有流程的哪一步

```
周报：组员交周报 → 组长筛选 / 分项目 → 各项目组报草稿 → 定稿（周报库）
                                                              ↓
月报：按月拉取这些「已定稿的按项目组报」 → 按项目预览总结 / 计划 → 各项目月报草稿 → 定稿
                                                              ↓
                                        导出 / 复制飞书 / 报送 SE（现有月报出口不变）
```

- **只认定稿**：周组报没定稿、没提交的周，不会被静默算进月报；需要显式确认才继续，并在月报开头标注。
- **不重复筛选**：周报阶段已经人工筛过一遍，月报只做「跨周合并 + 总结/计划归位 + 成文」，降低二次阅读。
- **不依赖 AI**：候选由代码按周组报正文排版；跨周完全相同的条目自动合并。AI 以后可作为可选的合并 / 润色，
  仍然只出草稿、必须人工定稿。
- **本期范围可调**：默认按周报日归属，但月初 / 月末可以在第 ① 步把上月最后一周、下月第一周纳入，
  或把月末这一周排除；只影响月报拉取范围，不影响周组报本身。
- **入口**：周报 tab 的「月」视角 → 月报首页（本项目 `MONTHLY · 2026-10 · 按项目`），进入月报整理。

## 三、月报口径（先定清楚，再谈界面）

| 项 | 口径 |
| --- | --- |
| 月份归属 | **默认建议值**：按周报日（默认周四）所在月份归属，沿用现有 `WeeksOfMonth` / `MonthOfWeek`。2026-10 默认 W40–W44，但本期周范围可以在第 ① 步改。 |
| 本期周范围 | 一组「整周」；默认 = 按周报日归属的周。可把上月最后一周 / 下月第一周纳入，也可把本月某周排除。见 3.1。 |
| 来源 | 本期各周、各**报送项目**的已定稿组报；不是组员原文，也不是未定稿的组报。 |
| 项目 | 沿用周报的「报送项目」配置（id / 名称），历史月份按当周快照显示，不随改名回溯。 |
| 本月总结 | 汇总本期各周组报的「本周总结」条目，跨周完全相同（规范化后）合并。 |
| 下月计划 | 以**本期最后一份纳入的周组报的「下周计划」**为底稿；更早的周计划默认折叠、不纳入，可手工结转。 |
| 不自动推断 | 不从总结里猜「已完成 / 未完成」，也不自动把旧计划判定为未完成；需要人拖动或补写。 |
| 缺周 | 只统计**本期范围内**的缺周；不阻塞，但必须勾选确认；月报开头用引用块标注 `未纳入：W44（未定稿）`。 |
| 正文署名 | 月报正文不带姓名、不带周次；自定义范围时开头标注 `本期范围：W39–W45（自定义）`。 |
| 生命周期 | 每项目独立：草稿 → 人工改 → 定稿 → 只读；导出 / 复制只认定稿。 |
| 文件命名 | `<组名>-组月报-<YYYY-MM>-<项目名>.md`。 |

### 3.1 本期周范围（月初 / 月末可调）

默认按周报日归属，所以 2026-10 默认是 W40–W44。但「这一周算不算本月」在月初 / 月末经常需要人判断，
所以第 ① 步把相邻两周也放出来，由人决定：

```
本期范围  W40–W44 · 5 周   默认按周报日归属            [恢复默认]
[ ] W39  上月最后一周   ← 可纳入：上月末的工作算本期
[✓] W40 … [✓] W44        ← 可取消：月末这周不算本期
[ ] W45  下月第一周      ← 可纳入：本月收尾延续到下周
```
（示意是默认状态；勾上 W39 / W45 后范围变成 W39–W45，取消 W44 后变成 W40–W43。）

- **整周为单位**：要么这一周算本期，要么不算；暂时不按天切（见待确认）。
- 默认只勾 W40–W44；W39 / W45 默认不勾，但能看到它们的定稿状态和条目数。
- 勾上相邻周 = 把它作为本期来源；取消本月的某周 = 从本期移除，缺周统计也跟着不算它。
- 典型用法：
  - 28 号要交月报、W44 还没定稿：取消勾选 W44，本期按 W40–W43 出，不触发 W44 的缺周提示；
  - 月初写上月月报，但上月最后一周的组报在月初才定稿：勾上 W39；
  - 月末写月报，想把下月第一周的收尾工作算进本月：勾上 W45。
- 范围只影响「月报拉哪些周」；每份周组报仍然只认定稿，未定稿的周不会被偷偷拉进来。
- 范围变化会让已生成草稿标「候选已更新」；定稿的月报只提示「来源已更新」，不自动改。
- 范围写入拉取记录和草稿 front matter（见第八节），下次打开、CLI、App 读同一份。

## 四、第 ① 步：拉取周报

```
本期 / 周        周报日      云平台项目                       数据中台项目
[ ] W39 上月最后一周 09-24   [已定稿 4 条 · 不在本期]        [已定稿 4 条 · 不在本期]
[✓] W40         10-01      [✓ 云平台项目 5 条 · 已定稿]     [✓ 数据中台项目 5 条 · 已定稿]
[✓] W41         10-08      [✓ 5 条]                          [✓ 6 条]
[✓] W42         10-15      [✓ 5 条]                          [— 未提交 · 不能纳入]
[✓] W43         10-22      [✓ 7 条]                          [✓ 6 条]
[✓] W44         10-29      [! 未定稿 · 不能纳入]              [✓ 6 条]
[ ] W45 下月第一周 11-05   [已定稿 4 条 · 不在本期]        [已定稿 4 条 · 不在本期]
```

- 左侧「本期 / 周」勾选框决定这一周算不算本期：默认勾 W40–W44，W39 / W45 不勾。
- 取消本月的某周 = 这周整体不算本期，缺周统计也不含它；勾相邻周 = 把它加进本期。
- 本周内的「项目 × 周」格子：**已定稿**才可勾选，未定稿 / 未提交显示原因且不可选；
  不在本期的周，项目格只读显示「已定稿 N 条 · 不在本期」。
- 「全选已定稿 / 清空」只动本期范围内的格；顶部实时统计：已纳入份数、候选条数（总结 / 计划）、缺周数。
- 每格有「原文」可打开当周组报只读预览；未定稿的也能查看，但明确标「不会纳入月报」。
- **缺周门禁**：本期内有缺周时必须勾选「已知 N 份未定稿 / 未提交，仍按当前纳入的 M 份整理」才能下一步；
  改周范围会重置这个确认；没有缺周时显示绿色提示，不出现确认框。
- 统计里的「候选」是去重、且**不含更早计划**（更早计划默认折叠）后的数量；第 ② 步会展示得更细。

## 五、第 ② 步：项目预览

```
┌ 2 个项目        │ 云平台项目                                   [报告预览] ┐
│ 云平台项目 13 条 │ 2026-10 · 来源 4 份周组报 W40–W43 · 候选 13 条        │
│ 数据中台项目16条 │ 未纳入 W44（未定稿）· 下月计划取自 W43                 │
│                  │ ┌ 本月总结 10 条 ─────────┐ ┌ 下月计划 3 条 ────────┐ │
│                  │ │ 完成退款接口联调…  W40 W41│ │ 对账服务全量发布… W43 │ │
│                  │ │ 合并 2 周               │ │                      │ │
│                  │ │ …                       │ │                      │ │
│                  │ └─────────────────────────┘ └──────────────────────┘ │
│                  │ ▸ 更早的计划 · 6 条（默认不纳入，可挑几条结转）          │
│                  │ 不纳入（拖到这里，或点条目里的「不纳入」）               │
└──────────────────┴──────────────────────────────────────────────────────┘
```

- 左侧项目栏显示候选数、来源周报数、草稿状态；右侧是当前项目的两个池子。
- **本月总结**：来自纳入各周的「本周总结」，按周次排；跨周完全相同的条目合并成一条，显示周标签和
  「合并 N 周」；正文取最新一周写法。
- **下月计划**：默认只取最后一份纳入周组报的「下周计划」，标注取自哪周、最后一周为什么没纳入。
- **更早的计划**：默认折叠、不纳入；展开可「纳入计划」或「不纳入」。列表里的计划和总结可以互相结转：
  总结项可「转为下月计划」，计划项可「移回本月总结」。
- **拖动**：条目可拖到另一个池子或「不纳入」；点条目展开动作行，也可看来源周报 / 改归口。
  （原型用 HTML5 drag 演示；真实 App 建议 pointer events 自己做，避免 WKWebView 拖拽差异。）
- **报告预览**：只读弹层，按当前候选生成 Markdown，不调 AI、不改措辞、不带姓名 / 周次。
- **开始整理月报**：为每个项目各生成一份独立草稿，已有草稿不覆盖；跳第 ③ 步。
- 本期包含下月第一周时，「下月计划」底稿就取自那一周；包含上月最后一周时，总结会多出上月最后一周的条目。

## 六、第 ③ 步：整理月报

```
┌ 2 个项目        │ 云平台项目 · 月报                    [保存 ⌘S] [定稿] [导出] [复制飞书] ┐
│ 云平台项目 16 条 │ 2026-10 · 来源 6 份周组报（W39–W43、W45）· 总结 14 · 计划 2 · 草稿 │
│ 草稿 · 20:04    │ 未纳入 W44（未定稿）· 下月计划取自 W45。                        │
│ 数据中台项目19条 │ ┌──────────────────────────────────────────────────────────┐ │
│ 草稿            │ │ > 本期范围：W39–W45（自定义）· 未纳入：W44（未定稿）          │ │
│                  │ │ ## 本月总结                                                │ │
│                  │ │ - 完成退款接口联调，覆盖 12 条用例……                         │ │
│                  │ │ ## 下月计划                                                │ │
│                  │ │ - 启动支付渠道接入开发。                                     │ │
│                  │ └──────────────────────────────────────────────────────────┘ │
└──────────────────┴────────────────────────────────────────────────────────────┘
```

### 6.1 独立保存的含义

| 动作 | 影响范围 |
| --- | --- |
| 保存（⌘S） | 只写当前项目这一份 |
| 保存全部 | 逐份写各自草稿，不合并内容 |
| 定稿 / 取消定稿 | 只锁 / 解锁当前项目 |
| 导出 / 复制 | 只导出当前项目 |
| 改来源 / 改归口 | 不动草稿，受影响项目标「候选已更新」 |
| 定稿后来源又变了 | 显示「来源已更新」，但不自动改定稿内容 |

- 每份草稿独立 `status`、`humanEdited`、`savedAt`、`.history`、`sourceHash`，切项目不互相覆盖。
- 自定义本期范围时，草稿开头多一行 `> 本期范围：W39–W45（自定义）`，导出给 SE 时也能看出月份边界。
- 来源变化不会自动重写草稿，避免把人工改好的措辞冲掉；要重来先取消定稿 / 点「按当前候选重新生成」。
- 已定稿的项目再改来源，只提示「来源已更新」，不自动改；需要人取消定稿后重新生成。

### 6.2 缺周与来源标注

- 草稿正文开头用引用块写 `> 未纳入：W44（未定稿）`；下月计划不是取自最后一周时，再写 `· 下月计划取自 W43`。
- 这是给人看的提醒，也是给下一级（SE）看的来源说明；定稿前可以手工删改。
- 编辑器里还有一条提示条，重复显示来源缺失 / 来源更新；定稿后仍保留。

### 6.3 导出

- 只认定稿；未定稿「导出 / 复制飞书」置灰（现有规则不变）。
- 文件名：`框架组-组月报-2026-10-云平台项目.md`；复制飞书同周报，只进剪贴板，不发送。
- 导入 SE：每个项目一份月报（与周报「每项目一份组报」口径一致），是否合并成一份由 SE 侧决定，见待确认。

## 七、月报首页

- 月份切换 + 按项目列表；顶部四个数：本期已定稿周组报、候选条数、项目数、已定稿月报数。
- 标题旁显示本期范围（`本期 W39–W45`），一眼能看出和默认按周报日的差别。
- 每行：项目 / 来源周组报 / 候选（总结 · 计划）/ 状态 / 操作（开始整理 · 继续整理 · 查看 · 导出）。
- 缺周、草稿来源变化、已定稿月报来源变化都在顶部用提示条列出，不藏在详情里。
- 定稿后进入「月报库」语义：可查看、可导出；要改先取消定稿。

## 八、数据与文件（落地草案）

### 8.1 月报草稿

沿用周报按项目组报的路径规则：

```
reports/2026-10/
├── group/
│   ├── p1/<组长 personId>.md      # 云平台项目月报
│   └── p2/<组长 personId>.md      # 数据中台项目月报
├── pull/<组长 personId>.md        # 本期拉取记录（只有 front matter）
└── product/product.md             # 产品月报（SE，不变）
```

- 草稿 kind 用 `group/<项目 id>`，与周报 `reports/<周>/group/<项目 id>/<组长>.md` 完全一致，复用
  `FinalDraftKind`、`.history`、索引与导出。
- 没有配置项目的工作台继续用旧路径 `reports/<月>/group/<组长>.md`（单份），首次配置项目时提示迁移。

front matter 在组报字段上增加：

```yaml
month: 2026-10
group: 框架组
person: "20261026-100000-9b3a"
name: 陈组长
project: p1
projectName: 云平台项目
status: draft                 # draft | final
weeks:                        # 本期周范围（自定义时可能含相邻周）
  - "2026-W39"
  - "2026-W40"
  - "2026-W41"
  - "2026-W42"
  - "2026-W43"
  - "2026-W45"
planFrom: "2026-W45"          # 下月计划取自哪周
missing: ["2026-W44"]         # 本期未纳入的周（状态 = 未定稿 / 未提交）
sources:                      # 纳入的周组报
  - "2026-W39/p1"
  - "2026-W40/p1"
  - "2026-W41/p1"
  - "2026-W42/p1"
  - "2026-W43/p1"
  - "2026-W45/p1"
sourceHash: "b31c9e…"         # 来源（纳入周 + 条目归口）的合并哈希
generatedAt: "2026-11-01T20:10:00+08:00"
editedAt: ""
finalizedAt: ""
humanEdited: false
```

### 8.2 拉取记录

`reports/<YYYY-MM>/pull/<组长 personId>.md`，只有 front matter、正文留空，沿用周报 `triage` 先例：

```yaml
month: 2026-10
group: 框架组
lead: "20261026-100000-9b3a"
updatedAt: "2026-11-01T20:05:00+08:00"
weeks:                           # 本期周范围；默认按周报日，改过就记全量
  - "2026-W39"
  - "2026-W40"
  - "2026-W41"
  - "2026-W42"
  - "2026-W43"
  - "2026-W45"
included:                        # 本期实际纳入的周组报；其余未定稿 / 未选的不写
  - { week: "2026-W39", project: p1 }
  - { week: "2026-W39", project: p2 }
  - { week: "2026-W40", project: p1 }
  - { week: "2026-W40", project: p2 }
  - …
overrides:                       # 只记偏离默认的归口
  - { project: p1, week: "2026-W42", section: 本周总结, item: "a1b2c3d4", pool: plan }
  - { project: p2, week: "2026-W43", section: 更早计划, item: "e5f60718", pool: excluded }
```

- 条目本身不落盘，每次从周组报正文解析；`item` 是 `sha256(project + section + 规范化文本)` 前 8 位。
- 默认池：总结 → `summary`、最后一周计划 → `plan`、更早计划 → `archive`；`overrides` 只存改过的。
- 周组报正文改了 → 条目 id 变，旧 override 失效，新条目按默认归位；草稿 `sourceHash` 不一致 → 候选已更新。
- `sourceHash` 由「本期周范围 + 纳入的周组报 + 条目归口」合成；只改范围也会让草稿标「候选已更新」。
- 本期范围默认由 `WeeksOfMonth` 算出；只有偏离默认时才需要写 `weeks`（也可以全量写，便于审计）。

### 8.3 周组报解析

- 固定节名 `## 本周总结` / `## 下周计划`，一级 `- ` 行为条目，`>` 引用和空行跳过。
- 只认一级条目；如果有缩进子条目，并入上一条（落地时定连接符），避免月报把层级带丢。
- 正文不带姓名、周次；周次只用于排序和来源标签。

## 九、边界与异常

| 场景 | 行为 |
| --- | --- |
| 某周组报未定稿 / 未提交 | ① 标灰不可选；勾选确认后继续；草稿开头标注未纳入 |
| 月初 / 月末边界周 | 在第 ① 步勾上 W39 / W45 或取消 W44；范围只影响拉取，缺周只算范围内 |
| 本期范围包含下月第一周 | 仍归本月月报；草稿开头标注本期范围，导出文件名仍按月份 |
| 本期范围改了 | 草稿标「候选已更新」；已定稿月报标「来源已更新」，不自动覆盖 |
| 某项目本期没有定稿周组报 | 可生成空草稿（「本月没有可纳入的总结条目」），人工补，不阻塞其他项目 |
| 周组报定稿后又改 | 草稿标「候选已更新」；已定稿月报标「来源已更新」，都不自动覆盖 |
| 跨周同一条目反复出现 | 规范化后完全相同才合并；措辞不同的不合并，靠人工删 / 并 |
| 一条总结其实要转计划 | 预览里点「转为下月计划」或拖到计划池 |
| 更早的计划 | 默认折叠不纳入；可展开逐条纳入 |
| 同一事项两个项目都要 | 不支持一条进两个项目；在月报正文里手工复制 |
| 项目改名 / 删除 | 历史月按周组报快照的 id / 名称；删除项目不静默改归属，旧月报保留 |
| 1 个项目 | 流程照走，只是只有一份月报；项目选择不消失（月报始终按项目） |
| 月报收集日 28 日 vs 最后一周周报日 29 日 | 见第十一节待确认；现在可在 ① 手动取消 W44 / 勾 W45，默认按整月 + 缺周标注 |
| 草稿人工修改后重新生成 | 先确认，旧版进 `.history`；已定稿先取消定稿（`9 HUMAN_EDITS_EXIST` / `--force` 沿用） |
| 断点恢复 | 拉取记录 + 各项目草稿即状态；步骤由它们推导，刷新 / 重启继续 |

## 十、CLI 与 App 草案

### CLI

| 命令 | 说明 |
| --- | --- |
| `report month sources [--month M] [--group G] [--json]` | 本期各周 × 项目的定稿状态、纳入情况、缺周与候选统计 |
| `report month scope --weeks W39,W40,…` / `--reset` | 调整本期周范围（可选相邻周；恢复默认） |
| `report month pull --week W --project p1 [--off\|--on]` | 纳入 / 去选一份周组报 |
| `report month candidates --project p1 [--json]` | 按项目输出总结 / 计划 / 更早计划 / 不纳入 |
| `report month move <itemID> --project p1 --section summary\|plan --to summary\|plan\|archive\|excluded` | 改归口 |
| `report month generate --project p1` / `--all` `[--allow-missing] [--force]` | 生成 / 重新生成项目月报草稿（不调 AI） |
| `report month list [--month M] [--json]` | 列出各项目月报与状态、候选、缺周、来源是否更新 |
| `report month show\|edit\|finalize\|unfinalize --project p1 [--month M]` | 按项目操作 |
| `report export month-group --project p1` | 导出单个项目月报 |
| `report month generate --level product …` | 产品月报（SE）保持现有路径 |

## 十一、待确认

1. **月报收集日 28 日与最后一周周报日（2026-10 W44 = 10-29）错位**：
   - 现在可以在第 ① 步手动取消 W44 或勾 W45，先解决「这一次怎么交」；
   - 但默认口径仍要定：A. 月报改到次月初收，覆盖整月；B. 保留 28 日，默认只到 28 日已定稿的周；
   - C. 保留 28 日先交一版，最后一周定稿后补拉（与「定稿只读」冲突，需要补充版本规则）。
   原型默认按整月拉取、缺周标注，可手动调范围，等确认。
2. **下月计划来源**：现在是「最后一周计划 + 人工结转」。要不要用周报已有的「上周计划对比」数据，
   自动找出本期未完成的计划并带入下期计划？
3. **重复合并**：原型只合并规范化后完全相同的条目。要不要接 AI 做近似合并（仍只出草稿、人工定稿）？
4. **月报栏目**：周报有「风险与求助 / AI 经验」，月报是否只保留总结 + 计划，还是也带风险栏？
5. **上月计划完成情况**：月报常见「上月计划完成情况」章节，原型没做；要不要加？
6. **项目与产品线**：月报按项目，产品月报仍按产品线；SE 侧怎么对齐（项目映射产品线，还是两套维度）？
7. **多组**：月报拉取记录按组长隔离；项目配置现在是工作台级，多组共用项目列表是否合适？
8. **带进 SE**：每项目一份月报，还是像周报一样再合并成一份带项目标记的月报？
9. **整周 vs 按天**：现在本期范围只能是整周（W39 / W45 / W40–W44）。如果月初 / 月末需要只算
   9/28–9/30 这种「半周」，还要支持按天切吗？
10. **相邻周之外**：现在只把上月最后一周、下月第一周放出来；需要任意起止周 / 更远的周吗？

## 十二、原型说明

文件：[`report-month.html`](report-month.html)，单文件、无依赖，直接浏览器打开。
只演示 **2026-10**（W40–W44，两个项目），数据虚构，进度存本机 localStorage，右上角可重置。

建议按这个顺序试：

1. 首页 →「开始月报整理」：第 ① 步勾选 / 去选周组报，看统计和缺周确认；
2. **试本周范围**：取消 W44 → 缺周从 2 变 1、候选变少；再勾 W39 / W45 → 本期变 7 周、候选变多；
   点「恢复默认」回到 W40–W44；
3. 打开某周「原文」，看未定稿的 W44 不会被纳入；
4. 下一步：切项目，看总结 / 计划 / 更早计划；拖动条目跨池、点条目改归口、点「报告预览」；
5. 勾上 W45 后再看计划池：底稿变成 W45 的下周计划；勾 W39 后总结会多出上月最后一周的条目；
6. 「开始整理月报」：两个项目各生成草稿；改一份、⌘S 保存；自定义范围的草稿开头会有「本期范围」；
7. 切另一个项目，定稿、导出、复制；回第 ① 步改选周，再回来看到「候选已更新」/「来源已更新」；
8. 首页看状态、缺周与来源变化的提示。
