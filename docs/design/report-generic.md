# 通用组与周报库（原型）

> 状态：交互原型 [`report-generic.html`](report-generic.html)，示例数据，未改业务代码。
> 目标：把硬编码的「组长视图 / 汇总视图」收成通用的「组」能力，并给已定稿周报一个统一入口。

## 一、要解决的问题

1. 现在 App 固定两个 tab：一个看本组名单，一个看「交上来的汇总」，后者并不是真实组织，
   却和组放在同一层，导致每加一种角色就要再加一套流程。
2. 「组」只是组员文件上的一个字符串，没有实体，不能正经新增、改名、删除、换组长。
3. 组报定稿后散落在 `reports/<周>/group/...`，没有统一列表；一进周报就是当前组的名单。

## 二、模型

### 组是一等对象

- 组：`id / 名称 / 组长 / 成员`（先不做上下级）。
- 支持新增、改名、删除、换组长、批量挪成员；历史周仍按当时的组快照统计。
- 组内所有人机制相同：组员交周报 → 组长筛选 / 成稿 → 定稿。

### 只有一个组织实体：组

- 组就是唯一的组织单位，没有额外的汇总组或汇总角色。
- 周报库的「全部组」只是一个查看范围，不是组织。
- 如果以后要区分权限，再加查看权限，不需要新增组织实体。

### 定稿即归档

- 组报定稿后自动进入周报库，不再有单独的「交给下一层」步骤。
- 周报库按周 / 组 / 项目筛选，点开只读预览，可导出 / 复制飞书。
- 现有 lead 层数据保留只读兼容，不做破坏性迁移。

## 三、导航

| 入口 | 作用 |
| --- | --- |
| 周报库 | 所有组已定稿组报；默认入口，支持组 / 项目 / 周筛选 |
| 我的组 | 当前组的成员周报、组报状态；所有组同一套 |
| 组管理 | 组的新增 / 改名 / 删除 / 换组长 / 选成员 |

不再有固定的「组长名单 / 汇总」两个 tab。

## 四、原型

文件：[`report-generic.html`](report-generic.html)，单文件、无依赖，直接浏览器打开。

试玩：

1. 默认进入周报库，按组 / 项目筛选，点一行看只读定稿；
2. 「我的组」切换组，看成员周报与本周组报；
3. 「组管理」新建 / 编辑 / 删除组；
4. 右上角「全部组」只是查看范围，不是组。

## 五、待确认

1. 组之间是否需要上下级（组 → 上级组）？原型先扁平。
2. 默认入口用周报库，还是记住上次位置？原型默认周报库。

## 六、实现状态

已落地（分支 `report-generic`）：

- 组配置：`.kuibu/config.json` 的 `reportGroups`（id / 名称 / 组长）；成员仍由组员当前 group 决定；首次读取会从名单推导组。
- 组 CRUD：`report groups list|add|rename|rm|set`；App「组管理」页支持新建、改名、换组长、选成员、删除（有在职成员时拒绝）。
- 周报库：`report library [--week] [--json]`；App 默认进入「周报库」，扫描 `reports/<周>/group/**` 已定稿组报（含按项目分册），只读预览、导出/复制。
- 周报首页：`周报库 / 我的组 / 组管理`；固定层级 tab、月视图入口和旧的「交给下一层」按钮不再出现在界面。
- 历史第二层周报数据保留只读，不做删除或迁移。

未完成：旧组报/月报的 AI 入口仍在代码里但不再可达；旧数据的只读命令保留兼容。
