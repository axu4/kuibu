# 周报三步流程：筛选 → 项目分拣预览 → 分别整理各项目周报

> 状态：已实现（2026-10-28）。核心库 / CLI / App 三步流程已按本稿落地；已通过 Go 测试与前端
> typecheck/build，未在 Wails 真机 GUI 点验。可点原型见
> [`report-triage.html`](report-triage.html)，示例数据。
> 目标：小组收齐、条目化之后，组长在**一个流程**里走完：逐条筛选本周总结 / 下周计划 → 预览
> 每个项目拿到什么（可拖动调整）→ 分别整理每个项目的周报，每份草稿独立保存。

## 一、一句话

顶部一条步骤条：

1. **筛选**：一次一条，`1` / `2` 就是「采纳并放进项目 A / B」，`X` 移除，`空格` 待定；
2. **项目分拣预览**：按项目列出候选，还能预览每份组报的初始排版；
3. **整理周报**：每个项目一份独立草稿，左边切换项目，右边编辑；保存、定稿、导出都按项目各管各的。

## 二、放在现有流程的哪一步

```
收集周报（组员本来就一条一条写，已归档）
   → 解析成条目（直接读原文，不调 AI；归一稿只在原文拆不出条目时兜底）
   → ① 筛选（先本周总结，后下周计划）
   → ② 项目分拣预览（可拖动调整）
   → ③ 各项目组报草稿（各存一份）→ 整理 / 定稿 / 导出 / 报送
```

- **为什么在 AI 合并之前**：`report group generate` 会先让模型合并、去重、归类，生成之后
  「组员的每一行」已经被压缩，组长就没有逐行取舍的机会。筛选放在前面，候选集是确定的。
- **不依赖 AI 归一**：三步流程直接读组员**周报原文**，按「本周总结 / 下周计划 / 风险」标题或
  一行一条拆条目；原文拆不出时才退回已有归一稿。所以不配置大模型也能筛选、成稿、导出。
- **不再要求组员归一稿逐个定稿**：你们组员本来一条一条写，逐人定稿等于把同一批内容先读一遍；
  人工审阅改到筛选（留 / 弃 / 归口）和第 ③ 步组报编辑、定稿。成员归一稿保持草稿状态即可；
  如果个别组员原文不是按条的，仍可先归一/定稿，流程不等待。
- **产品原则不变**：组报必须人工编辑、定稿后才能导出 / 带入 SE；AI 只出草稿，这里连 AI 合并
  都省了，候选稿由代码按条目排版。
- **不强制**：没有筛选记录时，组报仍可走现有 AI 生成流程（需要成员定稿）；筛选一旦存在，
  生成只吃候选。
- **入口**：组报面板的「开始周报整理」进入第一步；已完成部分显示进度，可从任意步骤继续。

## 三、步骤条与流程规则

```
┌ 周报 | 周报整理 2026-W44 框架组                                 项目设置  键盘 ┐
├──────────────────────────────────────────────────────────────────────────────────────┤
│ ① 筛选 ✓ ── ② 项目分拣预览 ✓ ── ③ 整理周报        [上一步] [下一步：…]              │
│ 总结 9/9 · 计划 4/4 · 风险 2/2   2 个项目 · 13 条候选   2 份草稿 · 1 份定稿        │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

| 步骤 | 何时解锁 | 主要动作 | 完成标志 |
| --- | --- | --- | --- |
| ① 筛选 | 进入流程即可 | 本周总结 → 下周计划 → 风险，逐条采纳 / 移除 / 待定 | 三节全部判完 |
| ② 项目分拣预览 | 筛选全部判完 | 查看候选、预览报告、回改 | 点「开始整理周报」生成草稿 |
| ③ 整理周报 | 第 ② 步生成草稿后 | 每个项目独立编辑 / 保存 / 定稿 / 导出 | 各项目按需定稿（步骤条打勾） |

- **门禁**：没判完时点第 ② 步会提示「还有 N 条未判」；第 ③ 步要先生成草稿，不能从第 ① 步
  直接跳过预览。
- **可回退**：三步都可以点回去。回第 ① 步改判不会动已有草稿，只会让受影响项目的草稿标
  「候选已更新」（见第六节）；回第 ② 步只看不生成；第 ③ 步的「上一步」回到预览。
- **状态不额外落盘**：步骤状态由「筛选记录 + 各项目草稿」推导，没有单独的流程文件；
  刷新、重启、换设备打开都按同一套文件恢复。
- **不做四步**：没有单独的「完成 / 提交」页。第 ③ 步的「完成」会先保存未保存的草稿，
  再回到入口（可随时再进）；导出/复制就是最终出口。全部项目定稿后步骤条显示 ✓，仍可回退修改。

## 四、第 ① 步：筛选

### 4.1 布局

```
┌ 步骤条：① 筛选  ─ ② 预览  ─ ③ 整理        [还有 8 条未判] [下一步：项目分拣预览] ┐
├──────────────────┬───────────────────────────────────────────────────────────────┤
│ 本周总结  已判 3/9 │   张三 · 本周总结 · 支付                      第 4 / 15 条   │
│ 总结 3/9 计划 0/4 风险 0/2 │                                                          │
│                  │   参加周会与需求宣讲，整理会议纪要 1 份。                      │
│ 张三        3/7  │   看原文 E                                                     │
│ ● 完成退款接口联调… │   ───────────────────────────────────────────                  │
│ ● 排查线上超时问题… │   归入  [1 云平台项目]  [2 数据中台项目]                       │
│ ✕ 对账服务设计评审… │                        移除 X      待定 空格                   │
│ ○ 参加周会与需求宣讲 │   点项目名或用数字键 = 采纳并归入该项目；移除和待定随时可撤销。     │
│ – 补齐退款异常分支… │   上次：放入「云平台项目」· 张三   撤销 U                       │
│ 李四        0/5  │   ↑↓ 翻看 · E 原文 · U 撤销 · ? 键盘                           │
│ 底部：按项目计数   │                                                               │
└──────────────────┴───────────────────────────────────────────────────────────────┘
```

左侧队列按人分组，右侧只有一条卡片。队列负责「这一节还剩多少、刚才判了谁」，卡片负责
「这一条到底是什么」。

第 ① 步内部分两轮：**先过「本周总结」，再过「下周计划」**，最后是「风险与求助」。左侧三个
tab 显示各节进度；一节过完自动切到下一节并提示，不会把总结和计划混在一条队列里。筛完全部
自动进入第 ② 步。

### 4.2 卡片信息

1. **来源**：头像 + 姓名 + 栏目（本周总结 / 下周计划 / 风险与求助）+ 领域标签（条目自带
   【领域】前缀时拆出，正文里不重复显示）。这里读组员**周报原文**，没有原文时才退回归一稿；
   未定稿也照样能筛，不需要配置 AI。
2. **正文**：宋体大字，一条一行；这是判断的主体。
3. **原文**：默认收起；按 `E` 展开这位组员的整份周报原文（没有原文时显示归一稿），当前条目高亮。
4. **动作**：项目按钮 + 移除 + 待定。**点项目名 = 采纳并归入**，不再多一次「采纳」点击。

### 4.3 决策与按键

| 操作 | 键盘 | 结果 |
| --- | --- | --- |
| 采纳并归入项目 N | `1` `2` `3` `4`（或点项目按钮） | 进入该项目的候选 |
| 移除 | `X` / `⌫`（或点「移除」） | 进「已移除」，可恢复 |
| 待定 | `空格`（或点「待定」） | 进「待定」，不带入任何项目的候选 |
| 撤销上一步 | `U` / `⌘Z` | 回到上一条并恢复原状态 |
| 上一条 / 下一条 | `↑` / `↓`（`K` / `J`） | 只翻看，不改判 |
| 展开原文 | `E` | 当前卡片的原文抽屉 |
| 键盘说明 / 关闭 | `?` / `Esc` | 帮助弹层 |
| 只有 1 个项目 | `↵` | 采纳到唯一项目 |

- **只有 1 个项目时**：卡片上只剩一个主按钮「采纳 · 云平台项目」，项目键消失。
- **0 个项目时**：不进入流程，先引导配置；配置时默认用现有产品线预填。
- **已判条目**：卡片上显示状态条（已放入「云平台项目」/ 已移除 / 已待定），可以改判；
  改判后沿当前筛选队列继续。
- **先留后归口**：还没想好项目就按空格待定，第 ② 步点回去再归口。把「选项目」和「采纳」
  合成一步，是为了每条只按一次键。

### 4.4 节奏与进度

- 一节内一次决策自动进入本节下一条**未判**条目；本节过完自动进入下一节并提示；
  三节都过完自动进第 ② 步。
- 三个 tab 显示 `总结 9/9 · 计划 0/4 · 风险 0/2`，点 tab 可跳到某节回看或补判；
  回看时不自动跳到下一节，只在做出新决定时推进。
- 队列状态：`○` 未判、`●` 已采纳（副行带项目名）、`✕` 已移除、`–` 待定；
  每人的 `已判 / 总数` 和底部的按项目计数让组长随时知道分布。
- 顶栏进度是全局的；卡片右上角是「第 N / 15 条」。

### 4.5 持久化与容错

- 每次决策立刻写入本周的筛选文件（见第八节），关窗、崩溃、刷新都不丢。
- 重开时从「第一节里第一条未判」继续（一般是本周总结，再下周计划）；全部判完则从第 ② 步继续。
- 撤销栈只存在当前会话；重启后仍可从队列或预览页点回任意一条改判。
- 移除、待定都不是删除；改判不会动已生成的草稿，只会让草稿标「候选已更新」。

### 4.6 刻意不做的

- **不在筛选里改文字、合并、分类**：那是第 ③ 步的事；筛选只做「留 / 不留 / 归哪个项目」。
- **不做「全部采纳 / 全选」**：用户要的就是逐条看；批量入口会诱发误判。想快可以连续按
  `1` / `2`。
- **不做相似条目提示**：一期先靠人；后续可以加，但不应挡住主流程。
- **快捷键只在本模式生效**：不抢编辑器、不设全局快捷键。

## 五、第 ② 步：项目分拣预览

目的：确认「每个项目会拿到哪些条目」，顺手看一眼组报雏形，并且**允许直接拖动改归口**。

- **统计**：候选 N（按项目分开）、已移除 N、待定 N、已有草稿 N。
- **按节分区**：每个项目池内部再分 `本周总结` / `下周计划` / `风险与求助` 三块，
  一眼看出总结和计划各多少条，不再混在一起。
- **报告预览**：每个项目池上的「报告预览」打开只读弹层，展示该项目的候选稿：
  `## 本周总结` → `- 条目`（**不带姓名**），按栏目排好、不调 AI、不改措辞、不丢条。
- **拖动调整**：任意条目可以拖到另一个项目池，也可以拖到「待定」或「已移除」。
  拖动只改筛选记录里的归口，不动草稿内容；拖动后项目计数和草稿「候选已更新」立即更新。
  拖动时目标池有虚线高亮；点条目（不是拖）仍然回到第 ① 步定位改判。
- **移除 / 待定池**：同样可拖回项目；待定明确标注「不会进入任何项目」。
- **下一步**：为每个项目生成一份独立草稿，然后进入第 ③ 步；已有草稿的项目不会覆盖。
- **筛选改动后**：预览顶部提示「已有 N 份草稿基于旧候选」，第 ③ 步可逐份重新生成。
- 没有候选时「开始整理周报」置灰，提示回去筛选。

> 实现注意：真实 App 里建议用 pointer events 自己做拖动，不依赖 WKWebView 的 HTML5 DnD，
> 避免 Mac 上拖拽行为不一致；原型用 HTML5 drag 演示。

## 六、第 ③ 步：分别整理各项目周报

### 6.1 布局

```
┌ 步骤条：① 筛选 ✓ ─ ② 预览 ✓ ─ ③ 整理周报     [上一步] [保存全部（1）] [完成]   ┐
├──────────────────┬───────────────────────────────────────────────────────────────┤
│ 2 个项目  每份独立保存 │ 第 3 步 · 各项目组报                                        │
│                  │ 云平台项目 · 2026-W44                         [保存 ⌘S] [定稿]  │
│ 云平台项目  7 条   │ 7 条候选 · 来源 2 位组员 · 已保存 · 09:18      [导出] [复制飞书] │
│ 已保存 09:18      │ ───────────────────────────────────────────────────────────── │
│ 数据中台项目 6 条  │ ## 本周总结                                                 │
│ 已定稿            │ - 完成退款接口联调，覆盖 12 条用例……                        │
│                  │ - 排查线上超时问题……                                         │
│ 草稿是 Markdown，  │ ## 下周计划                                                 │
│ 各自一份           │ ……                                                          │
│                  │ 每个项目单独一份草稿，独立保存，互不影响。                     │
└──────────────────┴───────────────────────────────────────────────────────────────┘
```

左侧是项目列表（每项显示候选数 + 状态），右侧是该项目的草稿编辑器。真实 App 里编辑器沿用
现有组报面板的 Markdown 编辑器；原型用 textarea 代替，只演示交互。

### 6.2 独立保存的含义

| 动作 | 影响范围 |
| --- | --- |
| 保存当前（`⌘S`） | 只写当前项目这一份草稿 |
| 保存全部 | 逐份写各自草稿，不合并内容 |
| 定稿 / 取消定稿 | 只锁 / 解锁当前项目 |
| 重新生成 | 只重建当前项目，其他项目不动 |
| 导出 / 复制飞书 | 只导出当前项目这一份 |
| 第 ① 步改判 / 第 ② 步拖动 | 不改任何草稿；受影响项目标「候选已更新」 |

- 每份草稿有自己的文件、保存时间、`dirty` 状态、定稿状态和 `.history`；切换项目不覆盖另一份，
  未保存内容也不会因为切走而丢失。
- 原型是显式保存；真实 App 沿用组报面板的 800ms 自动保存，同时保留「保存全部」和按项目的
  保存状态显示。

### 6.3 草稿从哪里来

- 第 ② 步点「开始整理周报」时，按项目各生成一份：
  `## 本周总结` / `## 下周计划` / `## 风险与求助` → `- 条目`，只含该项目的候选，
  **不调 AI、不改措辞、不丢条**。
- **组报正文不带姓名**：给领导看的是事项本身。姓名只保留在筛选卡片和候选池里，方便追溯
  「这条是谁写的」；草稿、预览弹层、导出文件都不出现姓名（草稿 front matter 的 `sources`
  仍记组员 ID，供内部审计）。
- 1 个项目时只有一份草稿，步骤条第 ③ 步的副标题显示「1 份草稿」。
- 类别（功能开发 / 客户支持 / …）暂不出现；整理阶段可以人工补，也可以后续加「AI 归类」
  让模型在候选集内给类别和压缩措辞（仍走预览确认、人工定稿规则）。
- 草稿已人工修改 / 已定稿时，重新生成按现有规则返回 `9 HUMAN_EDITS_EXIST`，需要确认或
  `--force`，旧版进 `.history`。

### 6.4 候选变化（第 ① 步改判之后）

- 每份草稿记生成时的候选哈希；当前候选和哈希不一致时，项目列表和编辑器显示
  「候选已更新」，并给出「按当前候选重新生成」。
- 重新生成只影响当前项目，二次点击确认（人工修改会丢）；已定稿的项目要先取消定稿。
- 改判不会自动覆盖任何草稿，避免把组长已经整理好的措辞冲掉。

### 6.5 定稿、导出与结束

- 定稿按项目独立：定稿后只读；取消定稿后才能改；每份草稿的 `.history` 照旧。
- 导出 / 复制为飞书格式按项目单独进行，文件名区分项目：
  `<组名>-组报-<周>-<项目名>.md`。
- 全部项目定稿后步骤条第 ③ 步打勾；仍可回退修改。第 ③ 步的「完成」会先保存所有未保存的
  草稿，再回到入口，不会丢内容；入口显示「继续整理周报」。

## 七、项目配置

| 项 | 设计 |
| --- | --- |
| 位置 | 周报 tab →「更多」→「报送项目」；流程右上角「项目设置」也能进 |
| 数量 | 1 ~ 4 个；至少 1 个才能进入流程 |
| 操作 | 新增、改名（即时生效）、删除、拖拽排序（二期） |
| 名称 | 同组内唯一；改名不动 id，历史周按当周快照显示旧名 |
| 删除 | 先提示：已分到该项目的 N 条退回「待定」，该项目草稿归档到 `.history`；不静默改归属 |
| 1 个项目 | 筛选不出现项目选择（`↵` 采纳）；第 ③ 步只有一份草稿 |
| 历史周 | 筛选文件里存当周项目快照；改配置不影响已生成的历史草稿 |
| 与名单 | 纯报送口径，不动组员名单里的产品线 |

原型里的配置抽屉就是按这张表做的：改项目名，卡片按钮、预览池、第 ③ 步项目列表立即同步；
删掉第二个项目，条目退回待定，流程变成单项目模式。

## 八、数据与文件

### 8.1 工作台配置（`.kuibu/config.json`）

```json
{
  "version": 1,
  "reportWeekday": 4,
  "reportProjects": [
    { "id": "p1", "name": "云平台项目" },
    { "id": "p2", "name": "数据中台项目" }
  ]
}
```

- 没配置或空数组 = 不启用三步流程，行为与现在一致。
- 项目 id 稳定、名称可改；快照写进每周筛选文件和草稿 front matter。

### 8.2 每周筛选记录

`reports/<周>/triage/<组长 personId>.md`，**只有 front matter，正文留空**：

```yaml
week: 2026-W44
group: 框架组
lead: "20261026-100000-9b3a"
updatedAt: "2026-10-31T21:40:00+08:00"
sourceHash: "9f86d0…"          # 纳入条目的来源正文合并哈希（原文或归一稿）
projects:
  - id: p1
    name: 云平台项目
  - id: p2
    name: 数据中台项目
items:
  - id: "a1b2c3d4"             # sha256(person + 节名 + 文本) 前 8 位
    person: "20261026-100000-9b3a"
    name: 张三
    section: 本周总结
    domain: 支付
    text: 完成退款接口联调，覆盖 12 条用例，剩余 2 条异常分支待补。
    decision: accepted          # accepted | rejected | skipped
    project: p1                 # 仅 accepted 时有
    order: 1
    decidedAt: "2026-10-31T21:12:00+08:00"
```

- **节名**：现有归一稿的固定节名是「本周完成」，本流程展示为「本周总结」。落地时建议做
  显示别名映射（不改数据），或统一改名并迁移 `review.go` 的固定节名与默认模板。
- **为什么放 front matter**：结构化、App 和 CLI 共用、也能手改；和归一稿把 `review` 对比结果
  放 front matter 是同一个先例。正文留空，避免两份事实来源。
- **item id 含 person**：不同组员同文本不撞 id；文本改了 id 就变，按新条目处理。
- **sourceHash**：组员改稿后标「来源已更新」；新条目以未判状态补进队列，消失的条目
  标「来源已删除」、默认不进候选，由组长确认。筛选读原文优先，原文拆不出才用归一稿；
  成员归一稿是否定稿不影响筛选。
- **原子写**：沿用现有 `writeFileAtomic`。

### 8.3 各项目组报草稿

每项目一份独立文件：

```
reports/2026-W44/group/
├── p1/
│   └── <组长 personId>.md     # 云平台项目组报草稿
└── p2/
    └── <组长 personId>.md     # 数据中台项目组报草稿
```

front matter 在现有组报字段上增加：

```yaml
person: "20261026-100000-9b3a"
name: 组长
week: 2026-W44
group: 框架组
project: p1
projectName: 云平台项目
status: draft                 # draft | final
sourceHash: "b31c9e…"         # 生成时的候选哈希
sources:
  - "20261026-100000-9b3a"
missing: []
generatedAt: "2026-10-31T22:10:00+08:00"
editedAt: ""
finalizedAt: ""
humanEdited: false
```

- 每份草稿独立的 `status`、`humanEdited`、`.history`，互不影响；定稿后只读等规则不变。
- 旧工作台没有项目时沿用 `reports/<周>/group/<组长>.md`；第一次配置项目时提示把旧组报
  迁到第一个项目（或保留为历史），历史周不回溯改路径。
- 索引 ID 变成 `<周>/group/<项目 id>/<组长 id>`；`report list` 仍按周 / 人筛选，组报行多一个
  项目字段。
- 1 个项目时可以直接用 `group/<组长>.md`（配置了项目的单项目仍建议统一到 `group/<项目>/`，
  实现时二选一，别两种路径混存）。

### 8.4 导出

- 每项目一份定稿导出，文件名 `<组名>-组报-<周>-<项目名>.md`。
- 「复制为飞书格式」同样按项目单独复制。
- 带入 SE：每个项目写一份组长 `lead` 周报（`source: group-report` + 项目标记），还是合并成
  一份，见第十二节待确认。

## 九、边界与异常

| 场景 | 行为 |
| --- | --- |
| 有组员没交 / 原文拆不出条目 | 第 ① 步列出缺条来源，不阻塞其他条目；**不要求成员归一稿先定稿** |
| 筛选后组员重新提交 | sourceHash 不一致 → 标「来源已更新」；同步出新条目（未判），旧决策按 id 保留 |
| 条目文字被改 | id 变，旧决策留在记录里但标来源已删除；新条目未判 |
| 第 ① 步改判 / 第 ② 步拖动 | 不改草稿；受影响项目标「候选已更新」，可逐份重新生成 |
| 拖动到同一项目 / 相同状态 | 无操作，只提示 |
| 删除项目 | 提示影响条数；条目退回待定；该项目草稿归档 `.history`，不静默改到别的项目 |
| 新增项目 | 第 ③ 步显示「未生成」，可生成空草稿或从候选生成；其他项目不动 |
| 项目改名 | id 不变；筛选界面、预览池、草稿标题、导出文件名同步；历史周快照不变 |
| 组报已定稿 | 重新生成返回 `9`；先取消定稿 / 加 `--force`（旧版进 `.history`） |
| 只配置 1 个项目 | 筛选无项目键（`↵` 采纳）；第 ③ 步只有一份草稿 |
| 项目没有候选 | 生成空草稿「本周没有归入该项目的条目」，可人工补，不阻塞 |
| 同一事项两个项目都要 | 不支持一条归两个项目；在第 ③ 步把该行复制到另一项目草稿 |
| 组报正文姓名 | 不带姓名；姓名只在筛选卡片和候选池内部显示，导出和 SE 侧都不出现 |
| 分拣后有人离职 | 名单外人员条目照常显示，来源标姓名快照 |
| 跨周补做 | 按周独立；周切换器切到历史周可重新走三步 |
| 月报 | 组月报合并的是各周定稿组报，不重复筛选 |
| 多组 | 筛选文件按组长 personId 隔离；项目配置暂时是工作台级 |
| 断点恢复 | 筛选记录 + 各项目草稿即状态；步骤由它们推导，重开继续 |

## 十二、待确认

1. **「项目」和现有「产品线」是同一个口径吗？** 同一个就直接复用分章；两套维度的话，组报
   结构要加一层（项目 → 产品线 → 类别），或者项目只做报送筛选。
2. **待定项要不要带进草稿？** 现在完全不带入，第 ② 步提醒。也可以带成「（待确认）」。
3. **同一事项两个项目都要**：现在不支持一条归两个项目；第 ② 步拖动也只能二选一，需要吗？
4. **草稿初稿要不要默认跑 AI 归类**：现在不跑（确定性排版）；AI 归类作为第 ③ 步的可选动作。
5. **带入 SE 的方式**：两个项目各写一份组长周报，还是合并成一份带项目标记？影响 SE 侧
   产品报的汇总口径。
6. **成员级定稿还留不留**：本设计不要求筛选前逐人定稿，成员归一稿保持草稿即可；是否保留
   一个可选的「定稿」作为审计标记，不影响流程。

## 十三、原型说明

建议按这个顺序试：

1. 入口 →「开始筛选」：先只有「本周总结」的条目；连按 `1` / `2` / `X` / `空格`；
   本节过完会自动切到「下周计划」，左侧 tab 显示各节进度；

## 十四、和现有文档的关系
